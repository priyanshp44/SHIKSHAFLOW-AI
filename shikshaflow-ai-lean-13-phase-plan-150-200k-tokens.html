How Tokens Are Saved (The Rules)

Rule 1 — One file per prompt
Each Bob prompt produces exactly one backend file OR one frontend file. Never mix both in one turn.
Saves ~40K tokens in re-read overhead
Rule 2 — SQLite not PostgreSQL
Use SQLite for development. Zero config, no Docker, no connection string debugging. Switch to Postgres only for deployment.
Saves ~15K tokens in setup
Rule 3 — No Alembic migrations
Use SQLAlchemy create_all() for dev. Migrations add 10–15K tokens of setup with zero demo value.
Saves ~12K tokens
Rule 4 — Tailwind utility classes only
No custom CSS files, no component library setup. Pure Tailwind CDN classes inline. No design system tokens to define.
Saves ~20K tokens in styling code
Rule 5 — No test files in build phases
Tests are written only in the final phase, covering only the critical paths. No TDD during feature builds.
Saves ~30K tokens
Rule 6 — Flat state, no Zustand/Redux
React Context + useReducer for auth only. All other state is local useState. No global state library setup.
Saves ~10K tokens
Rule 7 — AI prompts are templates, not chains
Granite integration uses simple prompt templates with f-strings. No LangChain, no LlamaIndex, no agent framework overhead.
Saves ~25K tokens
Rule 8 — Merge thin phases
Original 21 phases → 13 phases by merging closely related work (e.g. Foundation + DB in one phase, Teacher Dashboard + Student Dashboard together).
Saves ~60K tokens in phase handoff overhead

Assessment + Scoring
MCQ, True/False — deterministic scoring in code
16K

Attendance + Analytics Merged
Streak tracking + performance data foundation for AI
16K
tokens
  • Daily attendance mark (present/absent) per student per class
  • Learning streak: consecutive days with task or assessment activity
  • Performance table: per-student, per-topic avg score calculated from AssessmentResult

8
IBM Granite — AI Teacher Assistant
Class-aware chat. First Granite integration.
16K
tokens
  • watsonx.ai SDK setup + IBM API key + model config in .env
  • Single /ai/chat endpoint: receives teacher message + class_id → fetches class context → builds prompt → calls Granite → returns response
  • Context injected: class name, subject, topic performance, weak areas, student count
  • Teacher: chat panel on dashboard — ask anything about their class
  • No streaming for now — simple request/response
Pattern: All AI calls use plain Python f-string prompt templates. No LangChain. No agent framework. Just direct API calls.

AI Content Generation + Task Approval
Granite generates tasks — teacher approves before assign
14K
tokens

  • Granite generates: title, questions (MCQ + T/F), answer key, explanation
  • Task saved as draft (approved=False)
  • Teacher sees draft: Preview → Approve & Assign / Edit / Reject
  • Only approved tasks reach students
  • Wire the Phase 5 "Generate with AI" button to this flow
Cut: Lesson plan generation, worksheet PDF export — task generation only
10
AI Feedback + Short Answer Scoring
Granite evaluates short answers, explains mistakes
12K
tokens
  • Short answer submissions sent to Granite with expected answer + student answer
  • Granite returns: score (0–N), identified mistake, feedback explanation
  • Feedback stored in AssessmentResult.feedback field
  • Student sees feedback after submission: "You scored 3/5 — Review how equivalent fractions are formed."
  • Teacher sees feedback in submission review
Cut: Bulk re-evaluation, feedback history comparison
11
Personalized Recommendations
AI generates next-step learning path per student
12K
tokens
  • Input: student's weak topics + recent scores + task completion
  • Granite returns: ordered list of 3–5 recommended steps (topic + activity type)
  • Stored in Recommendation table
  • Student dashboard shows recommendations list
  • Refreshed after each new assessment result
Cut: LearningResource catalog linking (recommendations show topic + activity description only, no external URLs)
12
At-Risk Detection + Teacher Intervention
The main Agentic AI demo workflow — end-to-end
14K
tokens
  • Rule engine: score < 55% + task completion < 60% + attendance < 80% → flag student
  • Status: 🟢 Normal / 🟡 Needs Attention / 🔴 High Support
  • Teacher dashboard: "N students need attention" → click → see flagged students + reason
  • Teacher clicks student → AI suggests remedial task for their weak topic
  • Teacher approves → task assigned → student gets it → submits → performance updated → teacher sees change
  • This completes the full intervention loop
Demo flow: This phase IS the final demo. Every prior phase feeds into this moment.
13
Hardening + Seed Data + Demo Prep
Polish, realistic data, critical bug fixes only
12K
tokens
  • Seed script: 1 teacher (Priya Shah), 6 students, 1 class (Grade 7-A Science), 3 tasks, 2 assessments, realistic scores

  • Input validation on all critical endpoints
  • Fix any broken flows from prior phases
  • README with demo walkthrough script
