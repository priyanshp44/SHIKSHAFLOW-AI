21-Phase Implementation Plan

# Phase Deliverables Layer
1
Foundation
Skeleton only — no AI, no auth
 React app + routing + layout shells. FastAPI app + health endpoint + CORS. Folder structure: frontend / backend / ai / database / tests. .env with DB URL, IBM keys. Infra
2
Database
All tables, relationships, migrations
 SQLAlchemy models for all 12 entities. Alembic migrations. Seed data (sample teacher, student, class). Relationship: Teacher → Class → Enrollment → Student. Infra
3
Authentication
Register, login, JWT, role routing
 Register/Login endpoints. Bcrypt password hashing. JWT access tokens. Role-based route guards (React). Auto-redirect: Teacher → Teacher Dashboard, Student → Student Dashboard. Unique ID generation (TCH-XXXX / STD-XXXX). Core
4
Class Management
Create class, join code, student enrollment
 Teacher: create class → auto-generate Class ID (CLS-1001) + join code (SCI7A24). Student: enter join code → enrolled in class. Teacher: view class list with student count. Remove student from class. Subject association. Core
5
Student Management
Student profiles, teacher's student list
 Teacher views full student list per class (name, score, attendance, tasks). Clicking a student opens profile: performance per subject, weak topics, task history, recent assessments. Student sees: enrolled classes, teacher name, their own profile data. Core
6
Teacher Dashboard
Real data control center
 My Classes list. Overview: total students, average score, attendance %, pending tasks, students needing support count. Per-class view: avg score, attendance, task completion, strong topic, weak topic. "N students need attention" alert with drill-down. Core
7
Student Dashboard
Engaging learning home
 Greeting + learning streak (🔥 N Days). Enrolled class info + teacher name. Today's tasks with status badges. Progress bar (overall %). Weak topics list. Recommended content preview. LeetCode-style feel. Core
8
Task System
Create, assign, submit tasks
 Teacher manually creates task (title, subject, topic, due date, marks). Assign to class. Students see task in dashboard. Student submits answers. Submission stored with timestamp. Teacher sees: assigned / submitted / pending counts + average score per task. AI draft flow (placeholder, wired in Phase 13). Core
9
Assessment Engine
MCQ, True/False, Short Answer
 Question model with type field. MCQ / True-False scored deterministically in code (no AI). Short answers stored for AI feedback (Phase 14). Score calculated, stored in AssessmentResult. Topic-level score breakdown. Student sees: score, correct/wrong, weak area. Teacher sees: class score distribution per topic. Core
10
Attendance & Activity
Daily tracker, learning streak
 Daily present/absent tracking. Learning streak calculation (consecutive active days). Activity counters: tasks completed, quizzes completed, learning time. Calendar heatmap on student dashboard (month view). Teacher sees per-student: attendance %, streak, task completion %. Core
11
Analytics
Performance data foundation for AI
 Student analytics: avg score, subject scores, topic scores, trend over time, weak/strong topics. Class analytics: class average, per-topic breakdown (strong/average/needs support counts), attendance and task completion rates. Performance model updated after every submission. This data feeds all AI agents. Core
12
AI Teacher Assistant
IBM Granite — class-aware chat
 Teacher types natural language queries. Granite receives class context (subject, topic, recent scores, weak areas) alongside prompt. Responses: lesson ideas, explanations, weak student list, remedial suggestions. Single assistant first — no multi-agent yet. IBM watsonx.ai SDK integration. AI
13
AI Content Generation
Lessons, worksheets, quizzes via Granite
 Structured prompts: class, subject, topic, difficulty, duration. Granite outputs: learning objectives, explanation, activity, questions, homework. Teacher reviews draft → Approve & Assign / Edit / Reject. No automatic assignment — teacher must approve. Generated task saved with ai_generated=true flag. AI
14
AI Assessment Feedback
Short answer evaluation + explanations
 Student short-answer → Granite evaluates → identifies mistake → generates explanation feedback. Score stored. Feedback shown to student post-submission. MCQ/TF continue to use deterministic scoring. Feedback also surfaced in teacher's submission review. AI
15
Personalized Recommendations
Student-specific learning paths
 Input: student profile + assessment results + task history + topic performance. Granite generates: ordered learning path (e.g. Fractions Basics → Equivalent Fractions → Quiz). Resources matched from LearningResource table. Displayed on student dashboard. Refreshed after each new assessment. AI
16
At-Risk Student Detection
Rule + AI flagging for teacher
 Rules: score declining + low task completion + poor attendance → flag. Status: 🟢 Normal / 🟡 Needs Attention / 🔴 High Support. AI generates reason sentence (not a label — a support signal for the teacher). Arjun example: 48% score, 82% attendance, 52% tasks → 🔴 + suggested action. Teacher sees list, not automatic action. AI
17
Learning Resources
IBM SkillsBuild + OER + teacher resources
 Resource catalog: title, topic, subject, difficulty, source, language, URL. Teacher can add custom resources. AI recommendation links resources to weak topics. Student sees resource list in dashboard and in recommendation path. Filter by topic/difficulty/language. Core
18
Teacher Intervention Workflow
Main Agentic AI demo workflow
 AI detects weak topic in class → Teacher dashboard shows insight → Teacher views affected students → AI suggests remedial task → Teacher approves → Task assigned → Students complete → New assessment → Performance updated. This is the core demo story covering all modules end-to-end. AI
19
AI Agent Integration
Wire all agents into service layer
 AI Service Layer routes requests to: Lesson & Content Agent, Assessment & Feedback Agent, Performance & Analytics Agent, Recommendation Agent. Each agent has defined input/output schema. No orchestrator yet — direct routing. All agents share class/student context from backend. AI
20
Security & Testing
Authorization, validation, test coverage
 Route authorization (teacher can't access other teacher's class). Input validation on all endpoints. JWT expiry + refresh. AI prompt injection hardening. Unit tests: models, scoring logic, streak calculation. Integration tests: auth flow, task submission, assessment scoring. AI tests: output format validation. Infra
21
Deployment & Demo
IBM Cloud + final demo flow
 IBM Cloud deployment (Code Engine / IKS). Environment variables for prod. DB migrations on deploy. Demo script: Teacher login → create class → students join → AI generates task → teacher approves → students submit → AI detects weakness → teacher intervenes → performance improves. Seed realistic demo data. Deploy

Key Workflows

1 — Teacher creates AI-generated task
Teacher→ Ask AI for task→ Granite generates draft→ Teacher reviews→ Approve / Edit / Reject→ Assigned to class→ Students receive task
2 — Student completes task + gets feedback
Student→ Opens task→ Submits answers→ MCQ/TF scored in code→ Short answers → Granite feedback→ Score + weak area shown→ Performance updated
3 — Teacher Intervention (Main Demo Flow)
AI detects weak topic→ Teacher dashboard alert→ Teacher views students→ AI suggests remedial task→ Teacher approves→ Students get task→ Students submit→ New assessment→ Performance improves→ Teacher sees progress
4 — Student joins class
Student registers→ Enters join code (SCI7A24)→ Matched to CLS-1001→ Enrollment record created→ Student dashboard shows class + teacher

Design Principles

Teacher always in control. AI never auto-assigns tasks or labels students. Every AI action requires teacher review and approval before reaching students.
MCQ and True/False scoring is deterministic code — never ask the LLM to calculate marks. Granite is used only for: content generation, short-answer evaluation, analysis, and recommendations.
Build one phase at a time. Each phase produces a working, testable module. No AI until Phase 12. No multi-agent architecture until Phase 19. Complexity grows incrementally.
